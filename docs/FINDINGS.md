# Знахідки та відхилення від плану

Журнал того, що виявилось у процесі і чого не було в [PLAN.md](../PLAN.md): технічні пастки, відхилення від задуманого, рішення.
Мета — щоб це можна було перенести у форк під **PoE2**. Кожен запис має позначку:

- **PoE2: так** — переноситься як є;
- **PoE2: перевірити** — ймовірно відрізняється, треба звірити з грою або PoE2-форком APT (Exiled Exchange 2);
- **PoE2: ні** — специфічно для PoE1.

---

## Етап 0 — хоткей, буфер, popup (26.10.2026)

### F-01. `Esc` не можна реєструвати через `RegisterHotKey`
- **Що сталося:** `tauri-plugin-global-shortcut` повернув `HotKey already registered` для `Esc`: клавішу вже тримала інша програма на ПК. Яка саме — не з'ясовано; для такої поширеної клавіші це нормально.
- **Рішення:** `Esc` ловиться низькорівневим хуком `WH_KEYBOARD_LL` ([platform/windows.rs](../src-tauri/src/platform/windows.rs)), увімкненим **тільки поки popup видимий**; натискання поглинається, щоб гра не закрила свої панелі.
- **Висновок:** глобально реєструвати тільки «рідкісні» комбінації (`Ctrl+D` тощо). Усе, що потрібно лише при відкритому popup, — через LL-хук.
- **PoE2: так.**

### F-02. Popup з `WS_EX_NOACTIVATE` + WebView2 працює
- Кліки по popup доходять до WebView, активне вікно не змінюється. Це був головний ризик R2 з плану — знято (перевірено на Блокноті, не в грі).
- `show()` з Tauri не використовується: показ через `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE | SWP_SHOWWINDOW)`, бо стандартний показ може активувати вікно.
- **PoE2: так.**

### F-03. `RegisterHotKey` треба викликати з головного потоку
- Плагін прив'язує хоткеї до вікна головного потоку, тому (де)реєстрація з потоку foreground-хука йде через `run_on_main_thread`.
- **PoE2: так.**

### F-04. Інструменти розробки: `POE_GAME_TITLE` і `POE_KEEP_POPUP`
- `POE_GAME_TITLE` — будь-яке вікно грає роль гри (Блокнот з текстом предмета).
- `POE_KEEP_POPUP=1` — popup не ховається при втраті фокусу. Потрібно для скриншотів: інструмент скриншотів Claude перемикає фокус на себе, і popup слушно ховався — виглядало як баг.
- **PoE2: так** (назва вікна — `Path of Exile 2`).

### F-05. Сторонні системні вікна забирають фокус
- `Windows Input Experience` (`TextInputHost.exe`: панель емодзі, історія буфера, сенсорна клавіатура) може стати активним і «залипнути»; тоді гра вважається неактивною, popup ховається, хоткеї знімаються.
- Зараз це поведінка за задумом. **Відкрите питання:** чи вважати такі системні вікна втратою фокусу гри. Вирішити після тестів у справжній грі.
- **PoE2: так.**

## Етап 1 — дані та парсер (26.10.2026)

### F-06. З 3.29 гра копіює тільки розширений формат, парсер APT старий формат модів не розбирає
- У 3.29 `Ctrl+C` завжди дає розширений опис (заголовки `{ Prefix Modifier "Name" (Tier: N) — Tags }`). APT примусово тисне `Ctrl` замість `showModsKey` з конфігу гри.
- Текст без заголовків `{ ... }` (як до 3.29): база й рідкість розпізнаються, **моди ігноруються** (`SECTION_SKIPPED`), без помилки.
- У розширеному форматі **немає хвоста ` (implicit)`** — тип мода видно із заголовка. Якщо дописати хвіст, мод потрапляє в `unknownModifiers`.
- **PoE2: перевірити** — інша комбінація для розширеного копіювання та інший формат тексту.

### F-07. Файли `*.index.bin` генеруються, а не зберігаються
- У репозиторії APT їх немає: їх будує Vite-плагін. Порт — [scripts/make-data-indexes.mjs](../scripts/make-data-indexes.mjs), запускається автоматично перед `start` / `build` / `test`; мови визначаються за папками в `public/data`.
- **Зсуви в індексах — це індекси символів JS-рядка (UTF-16), а не байти.** Тому файли даних не можна перекодовувати чи міняти закінчення рядків: у [.gitattributes](../.gitattributes) для `public/data/**` вимкнено `text` (у користувача `core.autocrlf=true`).
- **Генератора самих `items.ndjson` / `stats.ndjson` в APT немає** — їх можна лише брати з репозиторію APT щоліги.
- **PoE2: так** для індексів; **перевірити**, звідки брати дані PoE2.

### F-08. Код APT лишається незмінним завдяки `paths` у tsconfig
- Імпорти `@/assets/data` і `@/parser` ведуть у `src/lib/apt/*` (tsconfig `paths` + alias у [vitest.config.mts](../vitest.config.mts)). Файли парсера скопійовані байт-у-байт; змінено тільки `data/index.ts` (рядки позначені `// [port]`).
- Angular за замовчуванням вмикає `noPropertyAccessFromIndexSignature` і `noImplicitReturns`, на яких код APT падає (11 помилок). Обидва прапорці вимкнено; `strict` лишається (у TS 6 він увімкнений за замовчуванням).
- Коміт APT, з якого скопійовано, — у [src/lib/apt/UPSTREAM_COMMIT](../src/lib/apt/UPSTREAM_COMMIT).
- **PoE2: так** — той самий підхід до форку.

### F-09. Завантаження даних через підключуване джерело
- `fetch(import.meta.env.BASE_URL + …)` з Vite замінено на `DataSource`: у застосунку — `fetch` відносно `document.baseURI`, у тестах — читання з диска.
- `client_strings.js` — ES-модуль (містить `RegExp`), не JSON. У браузері — динамічний `import(url)`; у Node — `import()` через `data:`-URL (інакше Node сприймає `.js` як CommonJS).
- `patrons.json` не завантажується (потрібен лише екрану «Про програму» APT).
- **PoE2: так.**

### F-10. Тести: Vitest напряму, а не `ng test`
- Відхилення від плану: портований код — чистий TS без Angular, тому тести в `tests/` ганяються Vitest без Angular-збирача (`npm test`). Тестів в APT немає — приклади предметів написано вручну ([tests/items.ts](../tests/items.ts)).
- **PoE2: так.**

### F-11. Особливості даних, важливі для UI
- `matcher.string` зберігається **без знака** (`# to maximum Life`), а `stat.ref` — зі знаком (`+# to maximum Life`). Зараз popup показує рядки без «+» — виправити на етапі UI.
- `ParsedItem` **не містить назви рідкісного / унікального предмета** («Storm Loop») — лише базу в `info`. Назва береться з першої секції `rawText`.
- **PoE2: перевірити.**
