# Знахідки та відхилення від плану

Журнал того, що виявилось у процесі і чого не було в [PLAN.md](../PLAN.md): технічні пастки, відхилення від задуманого, рішення.
Мета — щоб це можна було перенести у форк під **PoE2**. Кожен запис має позначку:

- **PoE2: так** — переноситься як є;
- **PoE2: перевірити** — ймовірно відрізняється, треба звірити з грою або PoE2-форком APT (Exiled Exchange 2);
- **PoE2: ні** — специфічно для PoE1.

---

## Етап 0 — хоткей, буфер, popup (26.10.2026)

### F-01. `Esc` не можна реєструвати через `RegisterHotKey`
- **Що сталося:** `tauri-plugin-global-shortcut` повернув `HotKey already registered` для `Esc`: клавішу вже тримала інша програма на ПК. Яка саме — не з'ясовано; для такої поширеної клавіші це нормально.
- **Рішення:** `Esc` ловиться низькорівневим хуком `WH_KEYBOARD_LL` ([platform/windows.rs](../src-tauri/src/platform/windows.rs)), увімкненим **тільки поки popup видимий**; натискання поглинається, щоб гра не закрила свої панелі.
- **Висновок:** глобально реєструвати тільки «рідкісні» комбінації (`Ctrl+D` тощо). Усе, що потрібно лише при відкритому popup, — через LL-хук.
- **PoE2: так.**

### F-02. Popup з `WS_EX_NOACTIVATE` + WebView2 працює
- Кліки по popup доходять до WebView, активне вікно не змінюється. Це був головний ризик R2 з плану — знято (перевірено на Блокноті, не в грі).
- `show()` з Tauri не використовується: показ через `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE | SWP_SHOWWINDOW)`, бо стандартний показ може активувати вікно.
- **PoE2: так.**

### F-03. `RegisterHotKey` треба викликати з головного потоку
- Плагін прив'язує хоткеї до вікна головного потоку, тому (де)реєстрація з потоку foreground-хука йде через `run_on_main_thread`.
- **PoE2: так.**

### F-04. Інструменти розробки: `POE_GAME_TITLE` і `POE_KEEP_POPUP`
- `POE_GAME_TITLE` — будь-яке вікно грає роль гри (Блокнот з текстом предмета).
- `POE_KEEP_POPUP=1` — popup не ховається при втраті фокусу. Потрібно для скриншотів: інструмент скриншотів Claude перемикає фокус на себе, і popup слушно ховався — виглядало як баг.
- **PoE2: так** (назва вікна — `Path of Exile 2`).

### F-05. Сторонні системні вікна забирають фокус
- `Windows Input Experience` (`TextInputHost.exe`: панель емодзі, історія буфера, сенсорна клавіатура) може стати активним і «залипнути»; тоді гра вважається неактивною, popup ховається, хоткеї знімаються.
- Зараз це поведінка за задумом. **Відкрите питання:** чи вважати такі системні вікна втратою фокусу гри. Вирішити після тестів у справжній грі.
- **PoE2: так.**

## Етап 1 — дані та парсер (26.10.2026)

### F-06. З 3.29 гра копіює тільки розширений формат, парсер APT старий формат модів не розбирає
- У 3.29 `Ctrl+C` завжди дає розширений опис (заголовки `{ Prefix Modifier "Name" (Tier: N) — Tags }`). APT примусово тисне `Ctrl` замість `showModsKey` з конфігу гри.
- Текст без заголовків `{ ... }` (як до 3.29): база й рідкість розпізнаються, **моди ігноруються** (`SECTION_SKIPPED`), без помилки.
- У розширеному форматі **немає хвоста ` (implicit)`** — тип мода видно із заголовка. Якщо дописати хвіст, мод потрапляє в `unknownModifiers`.
- **PoE2: перевірити** — інша комбінація для розширеного копіювання та інший формат тексту.

### F-07. Файли `*.index.bin` генеруються, а не зберігаються
- У репозиторії APT їх немає: їх будує Vite-плагін. Порт — [scripts/make-data-indexes.mjs](../scripts/make-data-indexes.mjs), запускається автоматично перед `start` / `build` / `test`; мови визначаються за папками в `public/data`.
- **Зсуви в індексах — це індекси символів JS-рядка (UTF-16), а не байти.** Тому файли даних не можна перекодовувати чи міняти закінчення рядків: у [.gitattributes](../.gitattributes) для `public/data/**` вимкнено `text` (у користувача `core.autocrlf=true`).
- **Генератора самих `items.ndjson` / `stats.ndjson` в APT немає** — їх можна лише брати з репозиторію APT щоліги.
- **Клонувати APT для синхронізації — тільки з `git clone -c core.autocrlf=false`.** Із `autocrlf=true` (налаштування користувача) Git перетворює дані на CRLF ще під час клонування; так перший імпорт потрапив у коміт із CRLF і був виправлений окремим комітом. Індекси при цьому працювали (будуються з тих самих файлів, `JSON.parse` терпить `\r`), але дані розходилися з upstream.
- **PoE2: так** для індексів; **перевірити**, звідки брати дані PoE2.

### F-08. Код APT лишається незмінним завдяки `paths` у tsconfig
- Імпорти `@/assets/data` і `@/parser` ведуть у `src/lib/apt/*` (tsconfig `paths` + alias у [vitest.config.mts](../vitest.config.mts)). Файли парсера скопійовані байт-у-байт; змінено тільки `data/index.ts` (рядки позначені `// [port]`).
- Angular за замовчуванням вмикає `noPropertyAccessFromIndexSignature` і `noImplicitReturns`, на яких код APT падає (11 помилок). Обидва прапорці вимкнено; `strict` лишається (у TS 6 він увімкнений за замовчуванням).
- Коміт APT, з якого скопійовано, — у [src/lib/apt/UPSTREAM_COMMIT](../src/lib/apt/UPSTREAM_COMMIT).
- **PoE2: так** — той самий підхід до форку.

### F-09. Завантаження даних через підключуване джерело
- `fetch(import.meta.env.BASE_URL + …)` з Vite замінено на `DataSource`: у застосунку — `fetch` відносно `document.baseURI`, у тестах — читання з диска.
- `client_strings.js` — ES-модуль (містить `RegExp`), не JSON. У браузері — динамічний `import(url)`; у Node — `import()` через `data:`-URL (інакше Node сприймає `.js` як CommonJS).
- `patrons.json` не завантажується (потрібен лише екрану «Про програму» APT).
- **PoE2: так.**

### F-10. Тести: Vitest напряму, а не `ng test`
- Відхилення від плану: портований код — чистий TS без Angular, тому тести в `tests/` ганяються Vitest без Angular-збирача (`npm test`). Тестів в APT немає — приклади предметів написано вручну ([tests/items.ts](../tests/items.ts)).
- **PoE2: так.**

### F-11. Особливості даних, важливі для UI
- `matcher.string` зберігається **без знака** (`# to maximum Life`), а `stat.ref` — зі знаком (`+# to maximum Life`). Зараз popup показує рядки без «+» — виправити на етапі UI.
- `ParsedItem` **не містить назви рідкісного / унікального предмета** («Storm Loop») — лише базу в `info`. Назва береться з першої секції `rawText`.
- **PoE2: перевірити.**

## Етап 2 — HTTP, ліги, rate limiter (26.10.2026)

### F-12. `Origin` не заважає API GGG — `unsafe-headers` не потрібен
- `tauri-plugin-http` завжди додає `Origin` (`http://localhost:4200` у dev, `tauri://localhost` у збірці); проксі APT його видаляв. Прибрати можна лише з feature `unsafe-headers`.
- Перевірено curl'ом 26.10.2026: `/api/leagues` і `POST /api/trade/search/<league>` відповідають 200 і без `Origin`, і з `tauri://localhost`. Плагін лишається зі стандартними фічами.
- `User-Agent` не входить до заборонених заголовків — його можна ставити з JS; без нього плагін шле `tauri-plugin-http/<версія>`.
- **PoE2: перевірити** (той самий сайт, але інші ендпоінти `/trade2`).

### F-13. Запити йдуть з Rust-сторони, cookies сесії поки немає
- APT робив усі запити через проксі в main-процесі з `useSessionCookies: true`. У нас — `tauri-plugin-http` без фічі `cookies`: CORS не заважає, заголовки `X-Rate-Limit-*` читаються, але cookies (POESESSID, Cloudflare) не зберігаються між запитами.
- Для ліг і анонімного пошуку цього досить. Ризик R1 (вбудований браузер, етап 7) лишається: доведеться ввімкнути фічу `cookies` або передавати cookies з WebView.
- Дозволені хости — у [capabilities/default.json](../src-tauri/capabilities/default.json): pathofexile.com, poe.ninja, poeprices.info.
- **PoE2: так.**

### F-14. Shim-модулі замість конфігу APT
- Код APT читає налаштування через `@/web/Config` (`AppConfig()`, `poeWebApi()`) і типи віджетів з `@/web/overlay/interfaces`. Ці імпорти через `paths` ведуть у [src/app/apt-shims](../src/app/apt-shims), тож файли APT, які на них спираються, копіюються без змін. Shim віддає тільки те, що реально читає портований код; розширюється разом із портом.
- Реактивність Vue в `RateLimiter.ts` / `common.ts` замінено на Angular signals (`revision`, `queue`, `RATE_LIMIT_RULES_REVISION`), логіку не змінено. `apiToSatisfySearch` тимчасово закоментовано до порту фільтрів (етап 3). `Cache.ts` — без змін.
- **PoE2: так.**

### F-15. Налаштування між вікнами синхронізуються через `storage`-подію
- Головне вікно і popup — окремі WebView2 одного origin. Налаштування (зокрема ліга) лежать у `localStorage`, а зміна в одному вікні приходить в інше через подію `storage` — перевірено: popup оновлює лігу без перезапуску.
- Тимчасове рішення до етапу налаштувань (план: `tauri-plugin-store`). Зауваження: у dev origin — `http://localhost:4200`, у збірці — `tauri://localhost`, тож dev- і prod-налаштування різні.
- **PoE2: так.**

### F-16. Ліги в 3.29 (Allflame)
- API віддає 16 ліг; після фільтра APT (без постійного HC, без `NoParties`, без `HardMode` поза подіями) лишаються `Standard`, `Allflame`, `Hardcore Allflame`. За замовчуванням — друга в списку (поточна челендж-ліга). Реальна відповідь збережена як [tests/fixtures/leagues.json](../tests/fixtures/leagues.json).
- Ліміт `/api/leagues` — політика `ladder-view`, `5:5:10,10:10:30,15:10:300`: легко вичерпати при ручному тестуванні.
- **PoE2: перевірити** (інші ліги та, ймовірно, `realm=poe2`).

### F-17. Статичні значення — в одному місці
- На прохання користувача всі налаштовувані значення винесено: TS — [src/app/constants.ts](../src/app/constants.ts) (UA, контакт, хости, realm, затримка API, ключ сховища, постійні ліги), Rust — [src-tauri/src/constants.rs](../src-tauri/src/constants.rs) (назва вікна гри, хоткей, таймінги буфера, ширина popup, мітки вікон, dev-змінні). Винятки: код APT і allowlist у capabilities.
- **PoE2: так** — для форку змінюються переважно ці два файли.

## Етап 3 — фільтри, пошук на trade, лістинги (26.10.2026)

### F-18. Структура папок `src/lib/apt` повторює APT
- Фільтри імпортують сусідів відносними шляхами (`../trade/…`, `../../background/Leagues`), тож `filters` і `trade` лежать у `src/lib/apt/web/price-check/`, як `renderer/src/web/price-check/` в APT. Перша спроба з «плоскою» структурою зламала `../../background`.
- `src/lib/apt/web/background/Leagues.ts` — не файл APT, а shim на місці: віддає лише `PERMANENT_SC` з `constants.ts`.
- Із 16 файлів фільтрів і `pathofexile-trade.ts` жоден не змінено: вистачило shim'ів `@/web/Config`, `@/web/background/IPC` (`Host.proxy` → `poeFetch`) і маски `@/parser/*` у `paths`.
- **PoE2: так.**

### F-19. Тексти UI: власний `t()` над `app_i18n.json` замість Transloco
- Відхилення від плану: APT уже має всі тексти у `public/data/<lang>/app_i18n.json`, і ключі фільтрів (`filters.preset_pseudo`, `item.item_level`, …) — це ключі звідти. Легкий `t()` + pipe ([core/i18n.ts](../src/app/core/i18n.ts)) дає мультимовність без окремої бібліотеки.
- На етапі 1 `app_i18n.json` не скопіювали (брали лише дані парсера) — виявилось лише зараз.
- **PoE2: так.**

### F-20. Фільтри APT змінюються на місці — `revision`-сигнал
- APT мутує об'єкти фільтрів напряму (`disabled`, `roll.min`, `expanded`), покладаючись на глибоку реактивність Vue. В Angular кожна зміна робиться так само на місці, а потім збільшується `revision`, від якого залежать `computed` панелі.
- Як в APT: зміни стат- і item-фільтрів чекають кнопки «Search», зміни онлайн-фільтрів одразу запускають пошук.
- **PoE2: так.**

### F-21. У popup поки немає вводу з клавіатури
- Popup — `WS_EX_NOACTIVATE`, клавіатура до нього не доходить. Min/max ролів і числові фільтри змінюються **колесом миші** (як слайдер APT), клік очищає або відновлює значення. Перевірено: колесо працює без активації вікна.
- Повноцінний ввід потребує тимчасового зняття `NOACTIVATE` і повернення фокусу грі — окреме завдання.
- **PoE2: так.**

### F-22. Групування лістингів не можна обрізати до показу
- Рішення «догружати ще» в APT рахує по **повному** згрупованому списку; обрізання до 20 рядків у тому ж `computed` змінило б це рішення і могло б дати зайві запити до API. Тому `groupedResults` повний, а `rows` — обрізаний.
- **PoE2: так.**

### F-23. Перевірено на справжньому trade API (Standard, 26.10.2026)
- Кільце з тестів: pseudo-пресет → «+110% total Elemental Resistance» (cold + fire + lightning), «+68 total maximum Life» (min 61 = −10%); окремий резист на вогонь прихований (`filters.hide_ele_res`). Пошук: «Matched: 8555», 20 рядків з ціною, iLvl і датою.
- API сортує за chaos-еквівалентом, тож у списку змішані валюти (chaos, chrome, vaal).
- Чіп рідкості показує сире значення (`nonunique`) — назва для UI на етапі дизайну.
- Стартовий ліміт клієнта — «1 запит / 5 с»; другий паралельний `fetch` стоїть у черзі, доки відповідь сервера не принесе реальні ліміти, після чого старий лімітер знищується і запит перепідписується на нові (покрито тестом).
- **PoE2: перевірити** — у PoE2 ендпоінти `/api/trade2/…` і інші категорії.

### F-24. «Відкрити на сайті» — системний браузер
- APT відкриває trade-сайт у вбудованому браузері; поки його немає (етап 7), посилання відкривається через `tauri-plugin-opener` у системному браузері.
- **PoE2: так.**
